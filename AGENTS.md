# LOCUSTAF — Agent Context

## Commands
- `flutter analyze` — MUST run after any changes (0 issues required)
- `dart run seed/seed.dart` — Standalone seed script (no Flutter dep), reads `seed/seed_data.json`

## Seed Deployment Order
1. Deploy permissive rules: `firebase deploy --only firestore:rules firestore.rules.seed`
2. Run seed: `dart run seed/seed.dart` (creates Auth users + Firestore docs via REST API)
3. Deploy production rules + indexes: `firebase deploy --only firestore`

## Firestore Indexes
- 2 composite indexes on `attendances`:
  1. (userId ASC, checkInTime DESC) — attendance history queries
  2. (userId ASC, status ASC) — active attendance lookup
- Single-field indexes are auto-generated by Firebase

## Firestore Rules
- `firestore.rules` — Production (admin full, supervisor read-mostly, employee own-data only)
- `seed/firestore.rules.seed` — Permissive (all authenticated users read/write)
- Supervisor has read access to: users, workplaces, attendances, incidences (not medical_documents)

## Seed Data
- `seed/seed_data.json` contains: 1 admin, 1 supervisor, 1 employee, 1 workplace
- Admin default: admin@locustaf.com / Admin123!
- Uses Firebase REST API (dart:io HttpClient, no external deps)
- API key from `lib/firebase_options.dart`

## Key Architecture
- Feature-First + Clean Architecture (data/domain/presentation)
- Riverpod 3.3.2 (Notifier/AsyncNotifier, no StateProvider)
- GoRouter 17.3.0 with `refreshListenable` for role-based guards
- UserRole enum: admin / supervisor / employee (English strings, stored as-is in Firestore)
- Sidebar filtering: `_MenuItem.visibleFor: Set<UserRole>` + `userRoleProvider`
